# Timeline Grid

사진 여러 장에 각각 시각과 문구를 붙여, 하루의 흐름을 담은 타임라인 콜라주를 만들어 주는 웹 앱.
시각은 사진의 EXIF 촬영 시각에서 자동으로 채워진다.

3×2 여섯 컷이 한 장(3077×4096)이고, 사진이 6장을 넘으면 자동으로 다음 장으로 넘어간다.
업로드·합성·저장이 전부 브라우저 안에서 끝나므로 사진은 어디로도 전송되지 않는다.

## 레이아웃

레이아웃은 눈대중이 아니라 원본에서 측정했다.
[instagram.com/p/Daz6IEyEpT5](https://www.instagram.com/p/Daz6IEyEpT5/) 캐러셀 12장(각 3077×4096)을
내려받아 흰 행·열을 스캔한 결과, 12장 전부 아래 값에서 일치했다 — 사람이 매번 배치한 게 아니라 고정 템플릿이다.

| 항목 | 실측값 (3077px 기준) |
|---|---|
| 캔버스 | 3077 × 4096 |
| 사진 행 top | 0 / 1347 / 2695 (pitch 1347.5) |
| 사진 셀 | 1538.5 × 1032, 좌우 여백 0, 열 간격 0 |
| 캡션 밴드 중심 | 행 top + 1193 (= 사진 하단 + 161) |
| 캡션 | Tinos 45px, 행간 50px, 열 중앙 정렬 |
| 캡션 잉크 상자 | 445 × 42 (`04:56, Thursday, July 09`) |

`timeline.js`의 `SPEC`이 이 값들을 캔버스 폭 대비 비율로 들고 있다.

## 캡션 폰트

캡션 폰트는 7종에서 고를 수 있고, 그중 넷은 한글 글리프를 가진다.

| 폰트 | 한글 | 정규화 크기 |
|---|---|---|
| Tinos (기본 · 원본) | | 45.3px |
| EB Garamond | | 47.8px |
| Lora | | 40.5px |
| 본명조 Noto Serif KR | O | 39.2px |
| 고운바탕 Gowun Batang | O | 41.9px |
| 나눔명조 Nanum Myeongjo | O | 41.4px |
| 본고딕 Noto Sans KR | O | 40.4px |

폰트별 상수 표는 두지 않는다. 렌더할 때마다 `ctx.measureText()`로 기준 문자열(원본 첫 컷 캡션
`04:56, Thursday, July 09`)의 잉크 폭과 ascent/descent를 실측해서 세 가지를 유도한다.

- **크기** — 잉크 폭이 원본의 445px가 되도록 맞춘다. Tinos는 원래 값인 45px 부근으로 돌아온다.
- **위치** — 실측 ascent/descent로 baseline을 역산해, 잉크 밴드 중심을 행 top + 1193에 놓는다.
- **행간** — 잉크 높이 + 0.2em. 원본의 50px는 Tinos 잉크 0.911em에서 나온 이 규칙의 특수해다.
  50px로 고정하면 잉크가 1.08em인 본명조는 두 줄 간격이 1.4px까지 좁아진다.

기준 문자열을 고정하는 것이 핵심이다. 캡션마다 실측하면 한 행에 나란히 놓인 영문 캡션과 한글
캡션의 baseline이 서로 어긋난다. 원본 12장이 전부 같은 위치였다는 건 고정 baseline이었다는 뜻이다.
한글은 디센더가 없어 잉크 중심이 2~4px 위로 올라가는데, 모든 캡션이 같이 올라가므로 정렬은 유지된다.

한글 폰트의 Google Fonts CSS는 58~98KB(한글이 unicode-range 서브셋 90~124개로 쪼개져 있다)라서
`<link>`는 폰트를 고를 때 주입하고, `document.fonts.load(spec, text)`에 캡션 텍스트를 넘겨
필요한 서브셋만 내려받는다. 캔버스는 CSS처럼 글리프별 fallback을 해주지 않으므로 이 순서가 중요하다.

(정규화 크기는 Chrome / macOS 실측값이다. 폰트 렌더러에 따라 소수점은 조금 달라진다.)

## 미리보기 해상도

미리보기 캔버스는 CSS로 컨테이너 폭까지 늘어나므로(`width: 100%`), 비트맵은 **화면에 실제로 찍히는
디바이스 픽셀 수**여야 한다. `previewWidth(cssW, dpr)`가 그 값을 만들고, 컨테이너 폭은 캔버스를
DOM에 넣은 뒤 한 번만 잰다(모든 장이 같은 폭이다).

고정 620px이던 시절 Chrome/macOS DPR 2에서 잰 값:

| 창 | 캔버스 CSS 폭 | 620px 비트맵의 확대율 | 현재 비트맵 | 현재 확대율 |
|---|---|---|---|---|
| 데스크톱 (`.wrap` 1040 상한) | 962 | 3.10× | 1924 | 1.000× |
| 좁은 창 | 622 | 2.01× | 1244 | 1.000× |
| 모바일 375px | 313 | 1.01× | 626 | 1.000× |

CSS 폭만 보면 1.0배 근처라 멀쩡해 보이는 게 함정이었다. 흐림은 CSS 크기가 아니라 HiDPI에서 왔다.

폭이 3.1배가 되면 픽셀 수는 9.6배지만, 문구를 한 글자 칠 때마다 도는 `drawPages()`는
사진 12장(2장 분량) 기준으로 이 정도다 — 11회 중앙값, `getImageData()`로 래스터화를 강제한 값.

| 비트맵 폭 | 핸들러 동기 시간 | 래스터화까지 |
|---|---|---|
| 620 (이전) | 0.9ms | 2.2ms |
| 1924 (데스크톱) | 1.7ms | 4.9ms |
| 626 (모바일) | 1.2ms | 2.8ms |

한 프레임(16.7ms) 안에 여유 있게 들어와서 디바운스도, 입력 중 저해상도 렌더도 넣지 않았다.
DPR 3 폰이라도 313 × 3 = 939px로 데스크톱보다 작아서 모바일 상한도 두지 않았다.
상한은 내보내기 폭(3077)에만 걸어 둔다. 컨테이너가 962 CSS px를 넘지 않으므로 DPR 3.2부터 닿는다.

캡션 위치는 폭을 바꿔도 그대로다. 620 / 1282 / 1924 / 3077에서 렌더한 뒤 흰 행 스캔으로 잉크 밴드를
재고 3077 기준으로 환산했을 때, 밴드 중심과 `행 top + 1193` 사이의 오차는 Tinos가 ±2px,
본명조 + 한글 캡션이 −2~−6px으로 **모든 폭에서 같았다.** 한글 쪽 상수 오프셋은 기준 문자열이 라틴
문자열로 고정돼 있어 생기는 원래 성질이고(위 "캡션 폰트" 참고), 해상도와는 무관하다.

## 촬영 시각

카드의 시각 기본값은 사진에 박혀 있는 EXIF 촬영 시각이다. 파일 수정 시각(mtime)을 쓰면
AirDrop·다운로드·복사를 거친 사진이 전부 "옮긴 시각"이 된다 — 실제로 Hugo 테스트데이터의 카메라
JPEG 7장은 mtime이 죄다 `go mod`가 내려받은 2024-12-01이고, EXIF 쪽은 2010~2022로 흩어져 있었다.
12장을 손으로 고치는 건 이 앱의 요점을 무너뜨리므로, 읽을 수 있으면 읽는다.

폴백 순서는 `DateTimeOriginal`(0x9003, 셔터가 열린 시각) → `DateTimeDigitized`(0x9004, 카메라에서는
같은 값이고 스캔본은 이쪽만 가진다) → IFD0의 `DateTime`(0x0132, 편집 시각이지만 그래도 픽셀과 같이
따라다닌다) → 파일 mtime. 파서는 `timeline.js`의 `exifDateTime()`이고, `ArrayBuffer`(또는 그 뷰)를
받아 `Date | null`을 돌려주는 순수 함수다. 의존성은 없다.

- **읽는 것** — JPEG APP1 세그먼트 안의 TIFF 블록. 마커 체인을 따라 걸어서 `"Exif\0\0"`를 찾는다
  (바이트 검색으로 하면 픽셀 데이터에 우연히 있는 같은 바이트열이 걸린다). `II`/`MM` 양쪽 지원.
  파일 앞 **128KB만** 읽는다 — EXIF는 픽셀 데이터 앞에 있고, 12장을 통째로 메모리에 올릴 이유가 없다.
- **가둬 놓는 것** — TIFF 블록은 그 세그먼트 길이만큼 잘라낸 `DataView`로 읽는다. IFD는 값 오프셋을
  어디로든 돌릴 수 있어서, 파일 전체를 보는 뷰로 읽으면 손상된 블록이 **뒤따르는 세그먼트의 바이트를
  촬영 시각으로 내놓을 수 있다.** 뷰를 세그먼트에 가두면 같은 오프셋이 그냥 예외가 되고, 경계 검사를
  읽는 지점마다 흩뿌릴 필요도 없어진다.
- **타임존** — EXIF 촬영 시각에는 타임존이 없고, 있는 `OffsetTimeOriginal`(0x9011)은 일부러 무시한다.
  이걸 반영하면 도쿄에서 04:56에 찍은 사진이 콜라주를 만드는 곳의 시각으로 밀려서, 카메라가 보여준
  적 없는 시각이 캡션에 찍힌다. `formatStamp()`도 `datetime-local` 입력도 로컬 기준이다.
- **범위 밖** — HEIC/HEIF는 EXIF가 ISOBMFF item에 들어가는 다른 컨테이너라서 읽지 않는다(iPhone
  기본 포맷이다). PNG, 그리고 APP13에 실리는 IPTC/XMP 날짜도 읽지 않는다. 전부 조용히 mtime으로
  내려가고, 사용자는 언제든 카드에서 직접 고칠 수 있다.
- **개인정보** — EXIF에는 GPS도 들어 있다. 위 날짜 태그 셋(과 거기로 가는 포인터) 말고는 파싱조차
  하지 않고, 함수가 돌려줄 수 있는 것도 `Date`뿐이다. 내보내는 PNG에도 실리지 않는다 — 캔버스는
  픽셀 버퍼라 `drawImage` 시점에 컨테이너가 사라지고, 실제로 나온 청크는 `IHDR`/`IDAT`/`IEND`뿐이었다.

## SNS 공유

장마다 Instagram · Threads · X 버튼이 있다. 세 서비스 다 게시 API는 백엔드와 공개 이미지 URL을
요구하므로 쓰지 않는다 — 사진이 브라우저를 떠나는 순간 이 앱의 전제가 깨진다. 대신 브라우저가
그 환경에서 실제로 할 수 있는 것을 한다.

| | 조건 | 하는 일 |
|---|---|---|
| `share` | `navigator.canShare({files})` | OS 공유 시트. 여기서 앱을 고르면 그게 곧 업로드다 |
| `clipboard` | 시트 없음 · X/Threads | PNG를 클립보드에 넣고 `intent/post`를 연다. 붙여넣기 한 번 |
| `download` | 시트 없음 · Instagram, 또는 클립보드 불가 | PNG를 내려받고 컴포저를 연다 |

Instagram만 갈라지는 건 웹 컴포저가 파일 선택만 받기 때문이다 — 붙여넣기도, 인텐트 URL도 없다.
X와 Threads는 `?text=`로 문구를 미리 채운다(그 장에서 적은 문구들). 이미지를 URL로 실을 수 있는
서비스는 셋 중 없다. 데스크톱은 공유 시트가 있어도 Instagram·Threads·X가 OS에 등록돼 있지 않아
시트에 뜨지 않는다. 즉 `share`는 사실상 모바일 경로다.

분기는 `sharePlan()` 하나에 모여 있고, 기능 탐지 결과는 클릭 전에 이미 정해지므로 무엇이 일어날지
버튼 위에 미리 적어 둔다.

**공유본은 3077px이 아니라 1080px이다.** 두 가지 이유가 겹친다.

- Instagram이 2025년에 그리드를 3:4로 바꾸면서 1080×1440을 무크롭으로 받는다. 이 콜라주가 이미
  3077×4096 = 3:4다.
- `navigator.share()`는 클릭의 transient activation을 요구하는데, `ClipboardItem`과 달리 프로미스를
  받지 못한다. 핸들러 안에서 `await`를 하나라도 걸면 WebKit에서 `NotAllowedError`로 죽는다.
  그래서 blob은 클릭 **전에** 있어야 하고, 편집이 멎고 400ms 뒤(제스처 커밋과 같은 값) 미리 만들어
  둔다. 그 비용이 감당되는 게 1080이라서다 — 아래는 렌더 + 인코딩 실측(3회 중앙값, Chrome/macOS,
  `getImageData()`로 래스터화를 강제).

| 폭 | 래스터화 | PNG 인코딩 | 합계 | 용량 |
|---|---|---|---|---|
| 1080 × 1438 | 3ms | 29ms | 33ms | 99KB |
| 1440 × 1917 | 7ms | 41ms | 47ms | 138KB |
| 3077 × 4096 | 7ms | 186ms | 192ms | 478KB |

비용은 거의 전부 인코딩이고 픽셀 수를 따라간다. 내려받기는 3077px 그대로다.

(측정할 때 브라우저 탭이 백그라운드면 타이머가 1Hz로 클램프돼 전부 ~1초로 읽힌다. 폭을 바꿔도
값이 안 변하면 그걸 의심하면 된다.)

브랜드 아이콘은 인라인 SVG다. shadcn은 lucide를 쓰는데 lucide에는 브랜드 로고가 없어서 shadcn의
블록들도 직접 붙여 넣는다. 마크는 Simple Icons(CC0), 24 viewBox를 `currentColor`로 채운다.

## 구조

```
index.html        UI + 앱 로직
timeline.js       레이아웃 상수, 캡션 포맷, 미리보기 폭, EXIF 촬영 시각 파서, 공유 분기, 캔버스 렌더 (순수 함수)
timeline.test.mjs 실측값·EXIF·공유 분기 회귀 테스트
```

빌드 없음, 의존성 없음. 정적 파일 세 개가 전부다.

## 실행

```bash
python3 -m http.server 8123
```

`http://localhost:8123` 접속. (ES 모듈이라 `file://`로는 열리지 않는다.)

## 테스트

```bash
node --test timeline.test.mjs
```

레이아웃 기대값은 전부 원본 실측치다. 상수를 건드리면 여기서 깨진다.

EXIF 쪽은 픽스처 파일을 두지 않고 테스트 안에서 JPEG 바이트를 조립한다 — 바이너리 픽스처는 파서가
의존하는 오프셋을 전부 가리고, 정작 중요한 경우(빅엔디언, 잘린 헤더, 없는 태그)는 손에 있는 카메라가
만들어 주지 않는다. 유효한 파일의 바이트를 한 개씩 뒤집어 가며 `null`이나 정상 `Date`만 나오는지도
같이 확인한다.
